# Google Books exact-ISBN decision — 2026-08-12

Rosie's Books uses Google Books as its primary low-volume, server-side lookup of a single concrete edition by a valid, normalized ISBN-13. Every profile requires a nonblank Google Books API-key configuration; the test profile supplies a fixture value while production and development use `ROSIES_BOOKS_GOOGLE_BOOKS_API_KEY`. The key stays server-side and must be restricted to the Books API in Google Cloud. Open Library remains the fallback only when Google Books returns no matching ISBN.

The Google adapter searches with the ISBN constraint and accepts a returned volume only if its ISBN-10 or ISBN-13 normalizes to the requested ISBN-13. Google Books JSON, URLs, DTOs, and HTTP details are confined to `provider.googlebooks`; Open Library details remain confined to `provider.openlibrary`. The public boundary exposes provider-neutral edition data, outcome categories, and a constrained HTTPS cover reference only.

Policy: connect timeout is two seconds and each request has a five-second timeout. Google 5xx responses receive one retry; 429 responses preserve `Retry-After`; malformed data, other failures, and no-match results are not retried. Only a Google no-match calls Open Library. Caught lookup exceptions are logged server-side without book-query content or credentials. Development logs include full exception details by default; production logs only the exception class.

Accepted covers are fetched once and stored locally; ordinary library pages never hotlink them. A coverless provider edition with a canonical ISBN exposes an owner-scoped **Refresh cover** action: it may re-run exact ISBN lookup solely to obtain a trusted cover reference, then downloads it without changing bibliographic metadata. The downloader accepts only adapter-issued Google Books or Open Library URLs, applies its existing HTTPS, redirect, DNS/IP, byte, pixel, and image checks, and uses a local placeholder on failure. Google Books API and cover-use terms must be reviewed by the production operator before release; one accepted-cover fetch at this two-user volume is not crawling or bulk access.

Identity is deterministic: normalized ISBN-13 first; otherwise non-null `(provider_name, provider_edition_id)`; identifierless/manual editions are never fuzzy merged. If the two identifiers resolve to different editions, the add flow must surface an identifier conflict.

When a provider-confirmed add resolves an existing canonical edition, every canonical field is retained exactly as stored: title, subtitle, authors, format, publisher, publication date, page count, language, description, ISBN identifiers, provider identity, and metadata origin. Per-user private notes and metadata overrides are likewise retained. Provider data is only used when creating a previously unknown canonical edition; it never enriches or refreshes one. The separate explicit cover-refresh action is the sole exception: it may replace only a missing cover reference and asset.

Implemented: Add Book offers **Search by ISBN**. Deferred: title/author search must find works and show a bounded, paginated concrete-edition picker; it must not silently select a representative edition. Milestone 7 task 7-5 adds camera scanning as a separate progressive enhancement: EAN-13 detection immediately submits the ISBN lookup, typed entry remains available, and camera frames never leave the device.
